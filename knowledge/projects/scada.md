# PowerGrid SCADA 电力监控系统 · 项目说明

## 概况
- 个人作品集项目，由我一个人完成。演示：http://47.117.29.74:8088/ ；源码：https://github.com/rfs151/ai-scada
- 做什么：用潮流计算仿真一座 110kV 变电站，经 IEC 60870-5-104 规约接入主站，走通"厂站 RTU → 通道 → 前置 FEP → SCADA → 人机界面"真实链路：一次接线图拓扑着色、告警与 SOE、遥控（五防 + 选择-返校-执行）、故障注入与继电保护、事故追忆回放、事故简报、运行报表、负荷预测、数据校核。
- 和我工作经历的关系：延伸我在储能 EMS 里做的工业协议和电网业务；IEC 104 规约栈是我自己实现的。

## 架构
- rtu-sim（仿真子站）：pandapower 交流潮流，开关分合真实改变拓扑；保护与自动装置；IEC 104 从站。
- fep（前置机）：IEC 104 主站，建链、总召、对时、收数、下发遥控；品质处理、变化检测、SOE、报文记录。rtu-sim 和 fep 是两个独立进程，走真实 TCP 104 报文。
- redis：实时库 + 消息总线（Redis Streams 传变化数据、SOE、遥控命令、仿真控制）。
- db：TimescaleDB 历史库。api：FastAPI，REST + WebSocket，后台跑告警引擎、数据校核、遥控会话、历史写入、事故追忆。web：Vue 3。gateway：Caddy。

## 高频数据与并发处理
- 历史写入：Redis Stream 消费组 + 批量 COPY，写库成功才 ACK（至少一次）。
- TimescaleDB hypertable、1 分钟连续聚合、3 天后压缩、30 天保留；历史库只存变化，统计前按"前值保持"补齐分钟。
- 推送：按画面订阅、200 ms 合帧、只推增量，避免浏览器被高频变化淹没。
- 规则引擎消费 Redis 变化流和 SOE 流，越限回差与延时、检修抑制。
- 数据校核每 2 秒对实时断面计算一次，异常持续 15 秒才告警，避开短路暂态。

## 难点与解决
- **自研 IEC 104 规约栈**：APCI I/S/U 帧、15 位序号回绕、k/w 流量控制、t0～t3 定时器；ASDU 单/双点遥信（含 CP56Time2a SOE）、短浮点遥测、电度、遥控、设点、总召、对时；子站 SBO 及超时/撤销、否定确认；主站断线重连、STARTDT → 对时 → 总召 → 电度召唤。与 lib60870-C（c104）做双向互操作测试。
- **遥控安全**：会话状态机 pending → authorized → selected → done，任一步可撤销，选择后 30 秒超时自动撤销；五防校验 + 监护人确认；PBKDF2 口令 + JWT，全部操作写审计日志。
- **事故追忆**：保护 / 自动装置动作自动生成追忆，20 秒内的后续动作合并；回放数据 = 触发前 30 秒全站断面 + 窗口内全部遥测变化与 SOE，前端从断面出发逐条应用，接线图重现开关动作。
- **负荷预测选型**：仿真负荷没有气象、节假日特征，LightGBM 等模型只能学到同一时刻的历史值，所以选了可解释的相似日法（前 7 个仿真日加权平均、剔除偏离中位数 25% 的值、最近 1 小时滚动修正），离线回测约 99%；接口按"历史序列 → 预测序列"设计，可替换。
- **仿真时钟**：60 倍速，对齐本地时间，子站重启后历史数据的仿真钟点不变。
- **事故简报**：从追忆数据提取事实，按规则定性并给出处置建议；可选由大模型基于同一份事实撰写。

## 关键数据与技术栈
